# Refactor plan: DRY into the DDD structure

Turns [PONYTAIL_AUDIT.md](PONYTAIL_AUDIT.md) and [DUPLICATION.md](DUPLICATION.md) into independent lanes that drive the
[ARCHITECTURE.md](../ARCHITECTURE.md) check counts to 0. Base: main `3f8eb23`, 2026-10-02.

## Ground rules for every slice

- **Behaviour stays identical.** A deletion lands only where the audit shows it is unreachable (LSP: declaration is the only
  reference) or a byte-identical replacement exists. Anything else needs the slice's replay diff to come back empty.
- **Proof per slice:** the named suites (single files, under `capped`), then once per batch the gate `npm run test:app` + `tsc`
  + `oxlint` on touched files, plus `node scripts/check-boundaries.mjs`: the slice's target counts drop and no other count
  rises. Today's pass/todo baseline: 763 tests, 710 pass, 53 todo, 0 fail.
- **Replay diff** (where a slice moves sim code): before the change, run the named deterministic probe and save its output
  under `.bench/<lane>/`; after, run it again and `cmp`. Probes print numbers, not traces, and run under `capped` with a frame
  cap (ARCHITECTURE T6). Determinism of `npm run sweep` itself is not yet measured (the 01:28 reboot cut the double run short),
  so the first slice that relies on it runs it twice on an unchanged tree first.
- One slice = one commit = one lane. File ownership below is from the active-lane list; a "free" file still gets a heads-up to
  the lane whose suite covers it.
