# Query

Precisely describe on-screen HUD layout in Burnout 3 Takedown and Burnout Revenge races (where is the boost bar, its segmented look and colour, speed readout, position, lap, race timer, takedown counter) and in Need for Speed Underground 2 (tachometer with gear number in the middle, nitrous bar, speedometer digits, position and lap at top-left, minimap bottom-left). Which corner holds which element, and how big?

Burnout 3: Takedown and Burnout Revenge both use a compact, arcade-style HUD anchored mainly to the lower-left and lower-right corners, with the boost meter built as a segmented bar that grows with takedowns and can be extended up to 4x in Burnout 3; the manuals also describe the boost bar as turning bright orange when active, with a blue “earning boost” state before that.[1][2][9][11][13]

## Burnout 3: Takedown / Burnout Revenge race HUD
- **Boost bar:** lower-right area, shown as a horizontal segmented meter that can extend as you gain takedowns; the end state is a bright orange flame-like boost display, while the earned-but-not-fired state is blue.[1][2][9]
- **Speed readout:** near the boost area, paired with the race HUD rather than centered on-screen.[1]
- **Position / rival indicator:** upper-left style race info block, showing current position and rival/position context.[1]
- **Lap counter:** grouped with the upper-left race info, shown when applicable.[1]
- **Race timer:** displayed as a HUD element; in Burnout 3 the timer is normally only shown in the final seconds before an event ends.[8]
- **Takedown counter/combo:** part of the HUD tracking system, associated with the race-combat feedback and combos.[14]

## Need for Speed: Underground 2 race HUD
- **Tachometer:** large circular gauge on one side of the screen, with the gear number in the middle.[4]
- **Nitrous bar:** integrated with the tachometer cluster.[4]
- **Speedometer digits:** part of the same gauge cluster, with digital speed readout.[4]
- **Position / lap:** top-left corner.[4]
- **Minimap:** bottom-left corner.[4]

If a pixel-precise layout is needed, the surviving manual snippets confirm the element groupings and corners, but not exact pixel dimensions.[1][4]
